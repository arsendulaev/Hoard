## 1. Назначение

### Описание проекта

Проект позволяет иследователям хранить и систематизировать информацию об экспериментах. 

Участник иследования имеет возможность добавить карточку эксперимента в которой будут находиться вся необходимая инфомарция о эксперименте 
- Описание 
- Артефакты
- Метрики

## 2. Граница продукта

**В продукт входит:**

- Участник группы может производить следующие действия над экспериментами своей группы: 
    - Создать 
    - Удалить 
    - Сохранить
    - Изменить  
    - Прочитать 
- Хранить эксперименты в большом количестве с помощью сервиса  
- Иметь доступ *только* к своим экспериментам или экспериментам своей группы
- Приглашать пользователя по коду/ссылке в иследование

**Внешнее окружение и внешние системы:**

- Сервис не взаимодействует никак с другими сторонними сервисами

**Команда сознательно не реализует:**

- Динамические эксперименты, которые требуют автоматического обновления данных/метрик/логов 
- Удаление экспериментов и их данных в одностороннем порядке, то есть участник команды не может одной кнопкой удалить эксперимент а только после подтверждения кого другого участника команды
- Хранение бесконечного количества экспериментов в ислеование 

## 3. Пользователи и доступные действия

Внешний пользователь | не имеет никаких прав доступа к иследованию; Может создать своё иследование

иследователь | имеет возможность выполнить все доступные действия с экспериментом 
руководитель иследования | все права иследователя плюс приглашать другиз иследователей

## 5. Значимые данные и другие объекты

Исследование - к нему имеет доступ только Руководитель иследование (его создатель) 
И иследователи которых пригласил Руководитель 

Если доступ получает внешний пользователь - то он может удалить эксприменты внутри иследования что является удалением самой главной информации которая есть в сервиса 

Эксперимент - к нему имеет доступ только Руководитель иследование (его создатель) 
И иследователи которых пригласил Руководитель  

при раскрытие эксперимента, то есть получения к нему  доступа внешним пользователем, он сможет удалять/изменять/добавлять/читать данные об экспериментах или создавать непрвильные эксперименты котоыре буду сбивать и останавливаать иследование 
## 6. Компоненты и внешние взаимодействия

- Сервер 
- Клиент 
- База данных

Клиент заходит в аккаунт
Сервер производит все необходимые действия для аунтификации, верификации и авторизации пользователя в его учетную запись 
Обращается к Базе данных и выдает информацию об иследованиях и экспериментах в иследованиях которые связаны с данным аккаунтом

В базе храниться 
- Описание экспериментов 
- метрики 
- Артефакты 
В зашифрованном виде

сервер и база данных поднимаются в разных docker контейнерах
